# 动画持续制作计划

目标：让下一部新片从固定入口开始，减少搭环境、复制脚本和精修后改镜头的返工。

保留现有 Canvas / Three.js 绘制路线，复用确定性 `render(t)`、系列文字、音频时钟和 FFmpeg 导出。结构化采样工具已落地，使用方法见 [AI 检查手册](AI_INSPECTION.md)。**以下是待实施计划；新工具与统一接口尚未接入。**

## 1. 实施顺序

| 顺序 | 工作 | 完成标准 |
|---|---|---|
| 先收拢已有工具 | 修正旧检查、录制工具的失败处理；明确作品入口；固定依赖和浏览器配置 | 失败返回非零退出码；能从同一入口找到源码、构建、检查与导出方式 |
| 下一部新片试点 | 一个作品模板、开发预览、参数面板、统一运行接口 | 用一个真实镜头完成改参数、保存、重新打开、检查和导出 |
| 第二部新片验证复用 | 提取两部作品都需要的播放、文字、检查及少量画法 | 新片不再复制整套工具，构图、风格和节奏仍由作品决定 |
| 按实际瓶颈优化 | 单片性能、复杂时间轴、批量输出 | 有具体制作需求或测量结果，再扩大工具范围 |

第一批的具体改动：

- [check.js](../viz/tools/check.js)：运行错误、字体失败应影响退出码；比较采样覆盖实际时长和镜头切点，报告采样范围。
- [record.js](../viz/tools/record.js)：处理 FFmpeg 启动和退出失败，仅在编码成功后报告完成。
- 作品入口记录工作版、发布版、可编辑源码及构建／检查／导出命令；版本选择显式记录。
- 固定 Node 依赖和安装方式，统一浏览器配置。快速检查与完整视频导出分开运行。

## 2. 新作品的最小结构

| 部分 | 内容 |
|---|---|
| 作品配置 | 尺寸、帧率、时长、随机种子、结束方式（循环／停住）、可调参数 |
| 分镜与事件 | 镜头 ID 和起止时间；字幕、音效优先使用“镜头 ID＋偏移”，跨镜头事件可用全片时间 |
| 场景源码 | 每个镜头独立绘制；从源码构建，避免继续从上一版完整 HTML 切块继承 |
| 素材与声音 | 开发时独立存放，复用现有声音配置、来源记录和混音流程 |
| 发布产物 | 独立 HTML、MP4；开发源码与内嵌发布文件分开管理 |

预览、检查和导出共用四个接口：

| 接口 | 职责 |
|---|---|
| `ready` | 字体与必要资源准备完成 |
| `describe()` | 返回作品元数据、分镜、字幕和声音事件 |
| `renderAt(t)` | 绘制指定秒数的一帧，同一配置与时间产生相同画面 |
| `inspectAt(t)` | 返回当前镜头、实际相机、主要对象边界／接触点、当前文字等 JSON 状态 |

绘制与检查共用状态计算；对象位置注明坐标系，时间注明全片／镜头局部／旧素材映射含义。仅暴露关键对象。已有成片按需适配，新片先采用此约定。

## 3. 工具选择

| 工具 | 用途与引入时机 |
|---|---|
| [Vite](https://vite.dev/guide/) | 下一部新片采用：开发服务器、模块加载与快速预览 |
| [Tweakpane](https://tweakpane.github.io/docs/quick-tour/) | 下一部新片采用：相机、运动、光照等少量常调参数 |
| [Theatre.js](https://www.theatrejs.com/docs/latest/manual/sequences) | 经常需要编辑关键帧、速度曲线和多轨动作时再接入 |
| [Remotion](https://www.remotion.dev/docs/parameterized-rendering) | 同一模板需要大量文案、语言或尺寸变体时评估 |
| [Motion Canvas](https://motioncanvas.io/docs/) | 新做路线讲解、知识说明等矢量动画时评估 |

- Vite 默认构建包含独立资源，单 HTML 仍需专门打包，见 [资源处理](https://vite.dev/guide/assets)。
- 参数面板与 AI 使用同一份作品配置，修改结果保存回文件；相机、风等动态参数即时更新，静态构图参数触发对应缓存重建，初期可直接刷新。
- 保留 Playwright 与 FFmpeg 检查／导出链路，沿用现有音频主时钟。时间轴工具接入时服从同一渲染时间。

## 4. 每部片的制作流程

1. **明确体验与分镜**：一集的主要感受、记忆点；每镜头的主体、动作、运镜、时长和文字。
2. **先做动态草稿**：用简单形状跑完整段，提前检查切镜、运动、停留和文字节奏。
3. **逐镜头精修**：单镜头循环调参，保留全片预览、逐帧、安全区域及关键接触点覆盖层。
4. **检查与交付**：复用已有字速、缺字、边界和音画同步检查；查看关键帧与连续视频，再导出所需版本。

首个试点以“改参数 → 即时预览 → 保存并复现 → 读取结构化状态 → 导出”走通为完成标准。复杂时间轴和更多共享组件由后续作品的实际需求决定。

## 5. 排在制作流程之后的性能改进

- 汤泽：Canvas 滑雪回退资源按需初始化；同一帧的雪痕轨迹采样去重。
- 后续按启动耗时、预览响应和导出耗时定位瓶颈；保持现有画面和运动结果可比较。
